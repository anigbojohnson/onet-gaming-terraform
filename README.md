# Onet Gaming — Cloud Infrastructure

> Infrastructure-as-Code for the cloud backend powering **Onet: Connect & Match Puzzle** — a browser-based tile-matching puzzle game where players link pairs of identical images by connecting them within three lines to clear the board.

---

## About the Game

**Onet: Connect & Match Puzzle** is a web-based puzzle game built with **HTML, CSS, JavaScript, and Bootstrap**. Players are presented with a board of tiles and must match pairs of identical images by drawing a connecting path of **no more than three line segments** between them, with no other tiles blocking the path. The goal is to clear the entire board before time runs out.

This repository provisions and manages the AWS cloud infrastructure that hosts and serves the game — including web servers, application logic, and a managed database — across both development and production environments.

---

## Overview

This project uses **Terraform** to provision a production-grade, multi-tier AWS architecture in `eu-west-2` (London) and **Ansible** to configure the provisioned EC2 instances. A **Jenkins** pipeline ties everything together, supporting environment-aware deployments via Terraform workspaces (`dev` and `prod`).

## Terraform Modules

### `vpc`
Creates the VPC with a **3-tier subnet layout** across two availability zones:

| Subnet | Zone | Type | Tier |
|---|---|---|---|
| `pub_sub_1a` | eu-west-2a | Public | Web / ALB |
| `pub_sub_1b` | eu-west-2b | Public | Web / ALB |
| `priv_sub_2a` | eu-west-2a | Private | Application |
| `priv_sub_2b` | eu-west-2b | Private | Application |
| `priv_sub_3a` | eu-west-2a | Private | Database |
| `priv_sub_3b` | eu-west-2b | Private | Database |

### `nat`
Provisions NAT Gateways in the public subnets and configures route tables so private app and DB subnets can reach the internet outbound for updates and patches.

### `security-group`
Creates three security groups scoped to the VPC:
- **`web_sg`** — Applied to the ALB and web-tier EC2 instances (serves HTML/CSS/JS/Bootstrap to browsers)
- **`app_sg`** — Applied to app-tier EC2 instances (internal traffic only)
- **`db_sg`** — Applied to the RDS instance (accessible from app tier only)

### `key`
Generates and stores an EC2 SSH key pair used for Ansible access to both web and app instances.

### `rds`
Provisions a managed RDS database instance in the private DB subnets, with a dedicated subnet group spanning both availability zones.

### `alb`
Creates an Application Load Balancer in the public subnets to distribute incoming browser traffic across web-tier EC2 instances.

### `ec2` — Web Tier
Deploys EC2 instances that serve the game's static frontend (HTML, CSS, JavaScript, Bootstrap) to players' browsers. Count scales with the workspace:

| Workspace | Instances | Placement |
|---|---|---|
| `dev` | 1 | public subnet 1a |
| `prod` | 2 | public subnets 1a and 1b (multi-AZ) |

### `ec2` — App Tier
Deploys a single EC2 application server into the private app subnet (`app_subnet_1b`) to handle backend game logic and API requests.

### `route53`
Registers DNS records in an existing Route 53 hosted zone, pointing the game's domain to the ALB and optionally to an S3 static asset endpoint.

## Jenkins CI/CD Pipeline

```
┌──────────────────────────────────────────────────────────┐
│  Jenkins Pipeline  (parameter: TF_WORKSPACE = dev|prod)  │
│                                                          │
│  Stage 1 ─ Terraform Deploy                              │
│    • Create/select workspace (dev or prod)               │
│    • terraform init                                      │
│    • terraform apply -auto-approve                       │
│                                                          │
│  Stage 2 ─ Update Ansible Inventory                      │
│    • Read web_public_ips from Terraform output           │
│    • Write ansible/inventory/host.ini dynamically        │
│                                                          │
│  Stage 3 ─ Run Ansible                                   │
│    • SSH into EC2 instances (ssh-agent)                  │
│    • Run configure_ec2.yml playbook                      │
└──────────────────────────────────────────────────────────┘
```

### Required Jenkins Credentials

| Credential ID | Type | Description |
|---|---|---|
| `onet-gaming-aws-credential` | AWS Credentials | AWS Access Key & Secret for Terraform |
| `onet-gaming-project-ec2` | SSH Private Key | SSH key for Ansible to access EC2 instances |

### Pipeline Parameter

| Parameter | Options | Description |
|---|---|---|
| `TF_WORKSPACE` | `dev`, `prod` | Target environment for deployment |

## Usage

### Deploy via Jenkins
1. Open the pipeline job in Jenkins
2. Click **Build with Parameters**
3. Select `dev` or `prod`
4. Click **Build**

### Deploy Terraform Manually

```bash
cd terraform/root

# Select or create a workspace
terraform workspace new dev        # skip if already exists
terraform workspace select dev     # or 'prod'

# Initialise backend and providers
terraform init

# Preview changes
terraform plan

# Apply infrastructure
terraform apply
```

### Run Ansible Manually

```bash
cd ansible
ansible-playbook -i inventory/dev.ini playbooks/configure_ec2.yml \
  --private-key ~/.ssh/mykey.pem
```

## Variables

| Variable | Description |
|---|---|
| `project_name` | Name prefix applied to all AWS resources |
| `vpc_cidr` | CIDR block for the VPC |
| `pub_sub_1b_cidr` | Public subnet 1b CIDR block |
| `priv_sub_2a_cidr` | App private subnet 2a CIDR block |
| `priv_sub_2b_cidr` | App private subnet 2b CIDR block |
| `priv_sub_3a_cidr` | DB private subnet 3a CIDR block |
| `priv_sub_3b_cidr` | DB private subnet 3b CIDR block |
| `ami_id` | AMI ID for EC2 instances |
| `instance_type` | EC2 instance type (e.g. `t3.micro`) |
| `db_username` | RDS master username |
| `db_password` | RDS master password ⚠️ keep secret |
| `db_name` | Name of the game database |
| `db_subnet_group_name` | Name for the RDS subnet group |
| `domain_name` | Route 53 hosted zone domain |
| `s3_website_endpoint` | S3 static asset endpoint (optional) |
| `s3_website_zone_id` | Hosted zone ID for the S3 website |

> ⚠️ **Never commit sensitive values.** Store `db_password` and secrets in a `terraform.tfvars` file (add to `.gitignore`) or use AWS Secrets Manager.

## Notes

- `ansible/inventory/host.ini` is auto-generated by the pipeline — add it to `.gitignore`
- EC2 instances are accessed as the `ubuntu` user via SSH key authentication
- Terraform state is managed via a **remote backend** (configured in `providers.tf`)
- Public subnet 1a CIDR is hardcoded to `10.0.1.0/24` in the root `main.tf`
